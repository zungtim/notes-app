# 笔记 · 本地学习笔记与知识地图

这个应用用于把学习对话、论文阅读、个人思考和待解问题放在一起，并用关系图记录它们如何连接。

应用在本机运行。笔记、图片、持久草稿、界面偏好和默认导出保存为应用目录里的文件，不需要账户，也不上传到云端。浏览器显示界面；打开来源中的外部网址时，浏览器会访问对应网站。本版本不做跨设备同步，也没有 EXE 安装包。

## 启动与打开

在应用根目录双击 **启动笔记.cmd**，应用会在后台启动本地服务。电脑需要仍受支持的 Node.js LTS（最低22，推荐24 LTS）。启动器只使用已安装的 Node，不自动下载。随后在浏览器打开：

**http://127.0.0.1:4317**

使用结束时，先确认界面右上角显示“已保存在本地”，再双击 **停止笔记.cmd**。仅关闭浏览器不会停止后台服务；下次启动后可以继续使用已有笔记。

如果你使用终端，也可以进入应用根目录运行 `npm start`。这种方式需要保持终端打开，在终端按 `Ctrl + C` 可以停止服务。应用没有需要额外下载的第三方运行依赖，无须执行 `npm install`。

## 三层阅读结构

1. **主题**：先看较大的学习领域。一个主题可以包含很多笔记。
2. **逻辑图**：进入主题后，以节点和连线查看概念、问题与材料的连接。并列关系没有先后顺序；有方向的关系需要顺着箭头阅读。
3. **具体笔记**：选择节点，阅读或编辑正文、标签、学习状态与来源。把长推导和读图分析放在这一层，图中保留清楚的短标题。

关系图默认突出已审核的知识关系：并列保持同层，多个前置或应用可以汇合，反馈保留。明确的模块归属由包围模块卡片及其成员的分组框表达，同向同端点的学习顺序与科学关系共用一条线，悬停查看完整的两种说明。没有科学关系的后续章节仍保留顺序线。纯目录或不能准确分组的区域保留归属线；菜单的“查看全部关系”恢复全部独立箭头，不改变卡片位置和知识库。紫色虚线表示并列，棕色有向虚线表示知识前置；学习顺序不表示科学推导。阅读路线栏、卡片锁定入口和状态圆点继续移除。

排版先从已保存的知识关系确定层次，再安排卡片与连线。没有独立科学角色的目录模块置于组上方，避免父模块的归属线拉宽整张图；自身参与证据、前置等关系的模块继续按其知识角色排布。不强制所有卡片单排或固定三列，并列支路在上下分开，前置、后续和汇合内容向右展开。已有手工位置仍会恢复，点击“自动整理”才采用新排布；需要先查看效果时，可从既有菜单选择“重新排版（先预览）”。

模块已有基础或后续补充说明时，卡片直接显示对应角色。原有连接说明仍可在连线提示和笔记连接中查看，排版不会生成新的科学结论。

笔记整理助手负责结合正文、教材及已有记录审核关系，区分内容归属、知识前置、应用、并列和学习顺序，经版本接口保存。App 负责这些关系的排版和完整显示，不扫描正文猜测新关系。仅有相似标题、编号或空白正文时，不生成科学依赖；缺少依据时保留已有目录与连接。

节点位置、平移和缩放按主题与模块保存。新增卡片优先补在相关卡片附近。菜单的“仅整理连线”保持坐标与视口不动；“重新排版”点击“应用排版”才保存，取消或 Esc 恢复原图。可从菜单或 Ctrl+Z 撤销最近的布局调整，结构变动或离开当前图后撤销记录清空。

“模块外联系”的自动带入与展开功能已移除，模块画布只显示自己的内容；跨模块关系继续在框架总览及笔记连接中查看。底部说明当前连线数、由分组表达的归属数，以及已收起的关系和下级卡片数。若“排版提示”列出卡片冲突、关系循环、受阻连线或收起的说明，可展开定位；悬停或键盘聚焦连线可读完整联系。普通整理不修改正文、来源、学习状态或知识关系；根据教材补全关系由用户授权的笔记整理流程完成。

使用滚轮或工具栏缩放、“全图”查看全貌。大图默认保留可读缩放，完整结构可以比一屏更大；不必为了看全图把文字压得过小。

## 首次使用与已有笔记

仅有源码的新副本会创建空白笔记库，可以先添加主题，再新建笔记。已有 `data/notebook.json` 时直接继续使用其中的内容。`data/seed.json` 是可选的本地首次初始化文件；它与其他个人数据一样，不随源码发布，也不覆盖已有笔记库。

后续学习对话由你决定何时整理：当你明确要求“总结并生成笔记”或“记录到应用”时，再将内容存入笔记库。普通交流不会自动记为学习笔记；记录内容也不表示你已经理解或掌握。

## 怎样记一条实用的笔记

建议一条笔记只解决一个主要问题。开头说明问题、思路与结论，再沿同一条逻辑线展开定义、条件、必要推导或证据。图片、易混点与知识联系放在对应步骤旁，让公式与它解释的现象在同页相遇。实验、概念、方法和论文可以采用各自适合的组织方式。

可以记录概念、疑问、思考、论文和方法。学习状态用来表达“待整理—学习中—已理解—待复习”的当前进度，它由你决定。完成一次阅读并不需要立即标记为“已理解”。

正文支持Markdown标题、列表、加粗、引用、表格、代码、待办和网页链接。编辑已有笔记时，正文修改会自动保存；点击“完成并预览”可以查看格式。

新建笔记时，“复习模板”提供“问题与思路”和“理解过程”的起点；正文已有内容时不会被覆盖。标题可以按内容调整，应用不按“推导与展开”或“附图”等标题折叠正文。三个以上二、三级标题会生成“本页思路”，点击只滚动本页，不改变笔记路由或浏览器历史。点击笔记后默认专注阅读，右上角“关系图”可返回图与正文。知识连接及其已有说明在正文后可直接查看，完整来源记录按需展开，原始材料与删除操作仍由编辑功能管理。

助手的笔记整理规范由研究项目独立管理，不属于应用中的学习内容。

## 保存和查看图片

快速记录和已有笔记的正文编辑区都可以加入图片：点击 **“添加图片”**，将剪贴板中的图片 **Ctrl + V** 粘贴到正文，或将图片文件 **拖放到正文框**。可以一次选择多张图片；支持 PNG、JPEG、WebP、GIF，每张最大10MB。

图片会实际复制到应用目录的 **data/images**，保存完成后自动插入正文。快速记录仍需点击“保存笔记”才能提交这条笔记；已有笔记会自动保存修改。写入图片过程中请等待进度提示完成，再切换笔记或关闭页面。

在正文预览中点击图片可查看大图，用“＋／−”缩放，选择“原始大小”或“适应窗口”；放大后可拖动或滚动查看，Ctrl＋滚轮也可缩放。按Esc或点击关闭按钮返回，键盘Tab可依次访问大图控件。插入时文件名作为简短说明；编辑 `![说明文字](/images/…)` 可以修改，详细图注与读图提示写在相邻正文中。删除引用后原图继续保留，以便旧备份恢复。图片不会自动上传到外部服务。

外部网页图片地址和电脑文件路径不会直接变成正文图片。请先保存图片，再用上述方式插入；记录网页来源时仍可单独保留其链接。单条Markdown导出包含图片引用，跨电脑携带图片请使用完整JSON备份或复制应用目录。

**常用 LaTeX 公式支持离线数学排版。** 行内公式使用 `$E=h\nu$` 或 `\(E=h\nu\)`；独立公式用 `$$` 或 `\[` / `\]` 包围。支持分式、上下标、希腊字母、平方根、积分等常用语法，由浏览器原生 MathML 显示，无需联网。不支持的语法会保留原式；代码块始终显示原文。下列内容会显示为独立公式：

```text
$$
F = -\nabla U
$$
```

## 从不同来源快速记录

点击“新建笔记”，或按 **Ctrl + N**，粘贴内容并填写标题，选择主题、笔记类型、来源和状态，再点击 **“保存笔记”**。新笔记弹窗中的内容需要提交后才会进入笔记库；不要仅关闭弹窗或只按Ctrl + S。

来源类型有“对话摘录”“文献阅读”“自己的思考”“网页资料”和“其他来源”。学习对话可以写明对话主题；论文记录作者、年份、页码或图号，以及DOI或网页；自己的想法注明它是推测、疑问还是已经核实的结论。

一条笔记可以有多个来源。若同一条内容同时含有论文事实、对话解释和自己的判断，分别添加来源，并在正文中注明它们的对应部分。避免让一条来源笼统地承担整篇笔记的证据。

来源可以记录本地PDF等文件的路径。**本地路径只提供显示和复制，应用不会直接打开或上传文件，也不将文件内容复制到笔记库。** HTTP或HTTPS网址可以点击打开；DOI建议填写完整的 `https://doi.org/…` 链接。

## 关系怎样使用

| 关系 | 适合表达什么 | 例子 |
|---|---|---|
| 并列 | 同级概念，可以分别讨论 | 平均速度与速度展宽 |
| 分支 | 一个主题分成多个分支 | 超声速膨胀分别连接运动与内部态 |
| 延伸 | 沿着一个问题继续深入 | 速度分布延伸到相空间 |
| 前置 | 理解目标需要先理解起点 | 内部态是理解态依赖外场响应的前提 |
| 依据 | 起点支持目标的判断 | 飞行时间信号检验运动操控 |
| 辨析 | 标出差异、矛盾或容易混淆之处 | 减速与冷却需要分别判断 |
| 应用 | 将起点的方法或原理用于目标 | 外场响应用于分子束减速 |

为连线写一个短说明，通常比只选关系名称更有价值。例如“先确定内部态”可以说明这条前置关系为什么存在。

点击“添加关系”，选择起点、终点、关系和说明即可建立连接。也可以在笔记详情里点击“在图上选择要连接的节点”，选好关系后点击另一个节点；按Esc取消这次选择。

当前关系连接同一主题内的笔记。如果一条内容涉及多个领域，可保留在最主要的主题中，并用标签和正文链接记录其他领域的联系。

## 检索与整理

按 **Ctrl + K** 打开全局搜索，可以寻找标题、正文、标签、主题名和来源名称、链接、摘录中的关键词。多个关键词用空格分隔时，会寻找同时包含它们的笔记；按Enter可以打开第一条结果。

记笔记时，尽量保持术语一致，同时在正文加入常见别名，例如“飞行时间 / TOF”或“Stark效应 / 斯塔克效应”，以后更容易找回。

“全部笔记”提供类型、状态、来源、标签筛选，并可按更新时间、创建时间或标题排序。“待解问题”列出还未标为已理解的问题笔记；“待复习”列出你主动标记为待复习的内容。长正文不需要全放到标题里；清楚的短标题有助于图和列表同时保持可读。

| 快捷键 | 功能 |
|---|---|
| Ctrl + N | 打开快速记录 |
| Ctrl + K | 打开全局搜索 |
| Ctrl + S | 立即保存已经进入笔记库的修改 |
| Esc | 关闭弹窗，或取消图上的连接选择 |

## 保存、备份与恢复

实际笔记保存在 **data/notebook.json**。编辑后的修改会自动保存，也可以按Ctrl + S立即保存；以右上角 **“已保存在本地”** 为成功写入文件的标志。`data/seed.json` 只负责首次初始化，不是持续使用时的笔记文件。

每次成功保存前，应用会把此前版本保留到 **data/backups**，循环保存最近10个正文版本。这些版本通过本地路径引用 **data/images** 中的原图。长期备份建议使用“导入与备份”中的 **JSON导出**，它包含全部主题、笔记、来源、关系、节点位置，以及正文引用的图片文件。

导入JSON时，先预览主题、笔记、连接和图片数量，再确认操作。图片完整性检查和恢复成功后才会载入笔记。默认选择 **合并**，保留当前内容，并加入导入内容；满足去重条件的相同笔记会跳过。也可以主动选择 **替换**，完整改用备份中的内容，预览窗口会显示提醒，并提供“先备份当前内容”按钮。旧版文字JSON仍可导入；若旧备份只含图片链接，则需要原图已在当前应用中。

一条笔记的详情顶部还提供 **复制为Markdown** 和 **导出Markdown**，适合把正文、来源与相关连接带到其他文档中。Markdown导出只包含这一条笔记，不能代替完整JSON备份。默认 JSON、Markdown 和草稿导出直接写入本应用的 **data/exports/**；同名文件自动增加后缀，不覆盖已有导出。导出完成后按界面显示的文件名在该目录查看。

已经进入笔记库的编辑草稿保存在本应用 **data/drafts/**，界面偏好保存在 **data/preferences.json**；更换浏览器不会主动移动这些文件。重新打开时，可以恢复同一版本的草稿；如果笔记库已有较新的版本，可先将旧草稿导出到 **data/exports/** 再合并。服务断开期间，浏览器内存中尚未成功写入应用的修改仍可能丢失，应尽快恢复服务并保存，不能把持久草稿当成完整备份。未提交的新笔记弹窗不在已有笔记草稿的恢复范围内。

若两个窗口同时修改同一笔记库，较旧窗口的保存会暂停并提示版本冲突，避免直接覆盖另一窗口的修改。按提示先导出当前草稿，再读取最新笔记，并按需合并导入。

完整文件备份可以在确认保存、停止应用后复制整个 `data/`，其中包含笔记、图片、个人规则、自动备份、归档、草稿、偏好和默认导出。界面的JSON导出不包含个人规则、草稿和偏好；完整迁移优先复制整个 `data/`。同一磁盘中的自动备份不能防止磁盘损坏；需要时另行复制到自己的其他存储介质。

迁移到另一台电脑时，将 `data/` 放到具有相同数据格式的应用根目录，在已安装受支持 Node.js LTS（最低22，推荐24）的电脑上启动。`runtime/` 的进程文件、锁和日志留在原电脑，由新电脑重新生成；如果原始PDF也移动了，需要更新来源中的文件路径。两个电脑各自修改不会自动合并。

只向其他人分享程序时，使用经过检查的源码候选，不携带 `data/`、`runtime/`、`_workspace/`、`成果产出/` 或环境文件。对方首次运行得到空库和公共默认规则，个人规则与笔记不会随源码分发。

## 学习与记录流程

1. 继续阅读论文、提问或思考，先把一个问题弄清楚。
2. 需要沉淀内容时，告诉我“将这部分总结并记录成笔记”，并指出要记录的范围。
3. 记录时保留论文页码、图号、DOI、对话出处，区分文献事实、解释、推测与待解问题。
4. 必要时加入原图或自己的图示，并连接到已有的相关笔记；空库中的第一条笔记不需要强行建立关系。
5. 一轮学习结束，检查记录是否符合你的理解，并导出一份含图片的完整备份。

应用帮助保留思考过程和检索线索；科学结论仍应回到论文、教材和实验方法核对。学习状态由使用者决定，研究联系应以实际课题依据为准。

## 运行与验证补充

同一应用目录一次使用一个本地服务。启动器会复用已有实例，重复启动或改变端口参数也不会额外开启一个共享同一笔记文件的服务。不要同时手动运行多个 `node server.mjs` 进程来编辑同一个目录。

完整笔记正文的单次保存上限为64MB；含图片的JSON备份文件最大256MB，单张图片最大10MB。更大的长期资料库可以停止应用后复制整个目录备份。当前版本管理正文图片，PDF等其他附件仍以来源中的原文件路径或网页链接记录。

源码、个人数据与运行记录的目录说明见 [开发与目录管理](development.md)。`npm test` 会建立仅含源码与合成测试数据的独立副本，自动检查保存、版本冲突、备份合并、无效导入、图片、正文预览和规则初始化；测试输出不进入日常笔记目录。
