# 开发与目录管理

## 代码与本地数据

独立应用根目录同时容纳源码与本地私有数据。维护代码时按职责定位文件；用于 GitHub 或程序分享的候选仅从公开源码白名单生成，不包含日常数据。首次安装只需本应用文件夹，不依赖原研究工程。

```text
Notes-app/
├─ src/
│  ├─ server.mjs       # HTTP 服务、接口与本机访问限制
│  ├─ lib/             # NotebookStore、ImageStore
│  └─ public/          # 网页、公式、Markdown、关系图与图标
├─ scripts/
│  ├─ launch.ps1       # Windows 后台启动、实例复用
│  ├─ stop.ps1         # 核对身份后停止本应用进程
│  ├─ workspace.mjs    # 建立独立任务目录及缓存环境
│  ├─ Start-Task.ps1   # Windows 开发任务/续接入口
│  ├─ start.mjs        # 终端启动前配置内部任务环境
│  ├─ run-tests.mjs    # 创建源码副本后运行自动测试
│  ├─ prepare-release.mjs # 白名单源码候选与 SHA-256 清单
│  └─ maintenance/     # 明确授权后才能使用的历史维护工具
├─ tests/
│  ├─ *.test.mjs       # Node 内置测试
│  ├─ fixtures/        # 合成数据，不含个人笔记
│  └─ helpers/         # 独立浏览器测试服务与可选检查
├─ config/             # 公共默认模板
├─ docs/               # 使用和开发文档
├─ data/               # 本地个人数据，Git 忽略
├─ runtime/            # 正式运行记录，Git 忽略
├─ _workspace/         # 本应用任务、测试副本、缓存，Git 忽略
└─ 成果产出/           # 本地验证报告与截图，Git 忽略
```

根目录只保留项目说明、包配置、Git 配置、兼容入口和中文快捷命令。修改实现时编辑 `src` 或 `scripts`，避免在根入口再写一份相同逻辑。

## 本地数据的用途

| 路径 | 用途 |
| --- | --- |
| `data/notebook.json` | 当前完整笔记库，含主题、来源、关系与位置 |
| `data/images/` | 按内容哈希存储的原始正文图片 |

| `data/backups/` | 保存前的最近十个正文版本 |
| `data/archives/` | 明确维护任务保留的历史快照 |
| `data/seed.json` | 可选的本地首次初始化数据 |
| `data/preferences.json` | 本机应用的界面偏好 |
| `data/drafts/` | 应用文件中的待恢复草稿 |
| `data/exports/` | 默认导出的 JSON、Markdown 和冲突草稿；同名不覆盖 |
| `runtime/process.json`、`server.pid` | 启停所需的进程身份记录 |
| `runtime/launcher.lock` | 防止多个启动器同时启动同一目录 |
| `runtime/server-*.log` | 正式服务的标准输出和错误日志 |

空白副本不需要手工建立 `data`。首次读取笔记时创建空库，已有数据始终优先。助手工作规范在研究项目独立维护，应用不创建或读取。

界面中的 JSON 备份管理笔记和引用图片，不含草稿及偏好。停止服务后复制整个 `data/` 可同时保留这些内容和自动备份、归档、导出。原件和备份在同一磁盘上不能防止磁盘故障；需要异地备份时由所有者另行复制。运行记录不作为缓存批量清理，也不随数据迁到新电脑。

## 持续优化流程

1. 先读取项目约定和当前个人规则，确认这次改动针对的使用问题。
2. 在允许的任务工作区保存必要快照，修改明确涉及的源码文件。
3. 使用 `npm test` 运行独立源码副本中的检查。只有新的行为或回归风险需要增加测试。
4. 页面操作验证使用独立 QA 服务和合成数据；真实笔记页面检查以只读方式进行。
5. 明确确定的新规则记录日期、范围和要求，同步相关功能；不要把助手建议记成用户已确认规则。
6. 已核验报告放进新的成果目录，逐项核对中间文件用途后清理或保留。

## 测试工作区

阅读视图直接渲染保存的Markdown，不按标题推断附录或隐藏推导。`review.js` 从渲染后的标题构建本页滚动目录，放在开头说明之后；窄屏初次打开目录收起，正文与图不收起。目录不改hash或浏览器历史，也不从正文生成知识关系。来源审计可展开，知识连接显示已有label。`images.js` 的大图支持缩放、窗口适配、原始大小与拖动，并保留Esc关闭、Tab循环和焦点恢复。新增公式记号继续使用安全MathML子集，不执行HTML或SVG。

浏览器导航统一由 `src/public/navigation.js` 管理。主题链接沿用 `#/topic/<topicId>`，模块链接使用 `?scope=<moduleId>`，笔记使用原有 `/note/<noteId>` 路径并携带模块上下文。缺省主题链接回到总览；旧笔记链接推断所属模块；失效模块回到总览，仍有效的笔记则定位到其所属模块；失效主题回到首页，失效笔记关闭详情。标识一律使用 ID。用户导航通过 hash 产生原生历史项，`hashchange` 仅恢复页面；同一目标不重复入栈。仅在初始化规范化、失效链接修正时替换当前项。

上传期间主动导航继续被阻止。浏览器已后退或前进时，保留原编辑器直到图片插入或上传失败，再恢复浏览器最新目标；不改写被遍历的历史项。新建弹窗在这类历史回放中保留。切换模块前按旧图自己的 `viewKey` 刷新待保存视图，平移、缩放与分隔条不写导航历史。导航回归使用合成模块和笔记；程序调用前进、后退只能证明浏览器导航，不能代替物理鼠标侧键验证。

`npm test` 调用 `scripts/run-tests.mjs`。它先检查白名单 `src`、`scripts`、`tests`、`config`、`docs` 与固定根文件，然后逐文件复制到独立副本，不复制 `data`、`runtime`、`_workspace` 或个人成果。包含 `scripts` 是为了测试工作区和发布工具，同时支持 QA 入口相对导入。测试进程在副本目录运行，临时目录、Node 编译缓存、npm 缓存与测试数据指向本应用内部任务目录。

默认工作区为应用内 `_workspace/tasks/`。`NOTES_WORKSPACE_ROOT` 可改为本应用 `_workspace/` 内的其他任务子目录；词法越界、符号链接和 Windows 目录联接均被拒绝，不回退到父项目。创建前验证已存在的祖先目录及真实路径，环境路径在使用前重新验证。工具不自动清空历史任务。

Windows 每个新的开发命令进程先点调用：

```powershell
. .\scripts\Start-Task.ps1 -TaskName 'notes-development'
```

该入口设置当前进程的 TEMP、TMP、Node/npm/Python 等常见缓存环境并进入任务目录，不修改用户或机器级设置。PowerShell 新任务始终在标准 `_workspace/tasks/` 下创建，可用 `-ResumeTask '<目录名>'` 恢复；连续创建任务不会层层嵌套。JS 测试/发布工具可依据已校验的 `NOTES_WORKSPACE_ROOT` 嵌套到当前任务中，使用其打印的完整路径核查。工具输出、浏览器 QA profile、测试数据与日志均应显式位于内部任务工作区。

本工程控制自己的数据及这些工具参数。浏览器自身的配置、操作系统记录、已安装 Node/npm 启动前的全局配置不属于应用数据目录承诺，也不会被本工具擅自修改。运行开发工具时应先恢复上述进程环境；不要设置指向外部目录的缓存覆盖。

每次自动测试留存 `manifest.json`、`result.json` 和 `logs/test-output.log`，用于确认副本范围和实际结果。未运行的可选检查不能写成已通过。

浏览器测试辅助入口：

```sh
node tests/helpers/qa-server.mjs
```

它建立独立数据目录并使用合成 fixture，默认使用系统分配的空闲端口，打印 URL 与数据路径。用 `Ctrl+C` 停止。`image-qa-server.mjs` 提供同样隔离方式的图片测试入口。设置 `NOTES_QA_PORT` 可指定端口。

`image-ui-check.mjs` 是可选 Playwright 开发检查，不是运行应用或执行 `npm test` 的前提。它需要开发者另外提供 Playwright 模块和浏览器；可通过 `NOTES_PLAYWRIGHT_MODULE` 提供模块说明符或 `file:` URL，通过 `NOTES_BROWSER_EXECUTABLE` 指定已有浏览器。脚本自行启动独立 QA 服务，配置文件、截图与下载均写入 QA 工作区。没有预装浏览器时不应直接运行它触发外部环境操作。

开发测试仍使用合成数据。用户要求查看原笔记在新版中的实际呈现时，可另建明确标注的只读预览：`createAppServer({ readOnly: true, store, images, dataDir })` 注入纯读取的原库和原图适配器，不能对原库实例化会初始化目录的存储器，也不能复制真实库作为测试 fixture。预览返回 `X-Notes-Read-Only: 1`，界面显示“原笔记只读预览”；服务端拒绝笔记、图片、草稿、导出等写请求，仅允许把视图偏好存入当前工作树独立的 `dataDir`。验证写入隔离时使用合成数据；查看真实页面只读，并核对原文件前后校验值。普通启动默认仍可编辑。

## 启动与参数

使用仍受支持的 Node.js LTS，最低 22，推荐 24 LTS。Windows 启动器在探测 Node 前先恢复内部进程缓存环境，再从 PATH 找到 `node.exe`；也支持 `NOTES_NODE` 指定已有可执行文件。它不下载工具。根 `launch.ps1` 支持 `-NoOpen` 和 `-Port`；同一应用目录已运行时复用实例。服务用环境变量 `PORT` 指定端口，默认 `4317`，仅监听 `127.0.0.1`。

`npm start` 调用 `scripts/start.mjs`，配置内部任务环境后启动服务；无需 `npm install`，没有第三方运行依赖。Windows 普通使用优先双击中文快捷命令。当前不提供 EXE、不部署云端，不做设备间同步。直接运行 `src/server.mjs` 是底层开发入口，执行前须自行恢复内部任务环境。

根 `server.mjs` 保留旧命令兼容；新开发与文档统一使用 `src/server.mjs`。不要手动启动多个共享同一个 `data` 的进程。

`scripts/maintenance/clear-examples.mjs` 是早期清理示例笔记时保留的工具。它会写正式数据，既不在启动路径也不在测试路径；后续只有用户明确授权对应清理范围时才能运行，目录整理和常规检查不得调用它。

## GitHub 准备

源码候选仅包括 `config/release-files.json` 逐一列出的文件。该清单覆盖 `src`、`scripts`、`tests`、`config`、`docs` 中已确认的公共源码及 `SOURCE_FILES` 中的固定根文件，并包含清单本身。新增或删除公共源码时须逐项更新，不自动扩大范围。`.gitignore` 默认排除 `data`、`runtime`、`_workspace`、`成果产出`、根个人规则入口、开发缓存、依赖目录和环境文件；`.gitattributes` 约定源码文本换行，Windows 脚本使用 CRLF。

执行 `npm run prepare:release` 会先完成输入清单检查，再逐文件复制公开源码并比较 SHA-256，在内部任务目录产生 `source/` 与 `manifest.json`。白名单之外的根文件不复制；源码目录中出现未列入文件（即使扩展名为 JSON/Markdown）、私有目录、环境文件、密钥扩展名、链接或未知类型时失败，需要逐项确认后修正。命令不接受任意外部输出路径，不初始化 Git、提交、上传或选择许可证。将核验后的 `source/` 用作仓库内容或程序分享包；不要直接打包整个工作目录。

Git 忽略规则作用于尚未被追踪的文件。如果以后曾把个人文件提交到仓库，新增忽略规则不会自动从历史中移除它们。手动在 GitHub 网页上传也不会由本地忽略规则替你选择文件。

正式发布前核对候选清单、测试结果、实际文本及 Git 历史，再按所有者明确授权配置远端仓库。公开源码文件也可能被误写个人内容，路径白名单不能替代内容审查。接收者首次运行得到空库；只有所有者明确额外提供数据时才携带个人内容。许可证由项目所有者决定，当前未代为选择。
